# Zapret Manager — обзор проекта

## Что это и зачем

**Zapret Manager** — неофициальный графический менеджер (GUI) для [Flowseal zapret-discord-youtube](https://github.com/Flowseal/zapret-discord-youtube) под Windows. Он заменяет ручную работу с BAT-файлами: скачивает runtime Flowseal, запускает/останавливает zapret, помогает подобрать рабочую стратегию и обновляет runtime одной кнопкой.

Проект не связан с авторами Flowseal.

## Стек

- **Язык/платформа:** C#, .NET 8 (`net8.0-windows`)
- **UI:** Windows Forms (WinForms) + tray-иконка
- **Сборка:** single-file `.exe` через `tools/publish.ps1`, релизы — GitHub Actions
- **Тесты:** `tests/ZapretManager.Tests` (`dotnet test`)
- **Внешние зависимости:** runtime Flowseal (winws.exe, general*.bat), GitHub Releases API
- **Требования:** Windows 10/11 x64, права администратора (один запрос UAC при старте)

## Структура кода

Единственный проект — `src/ZapretManager.App`, разбитый по зонам ответственности:

| Папка | Назначение |
|---|---|
| `Core/` | Модели данных: конфиг, стратегии, статусы, результаты сканирования |
| `Services/` | Вся бизнес-логика (см. ниже) |
| `System/` | Запуск внешних процессов (`CommandRunner`) |
| `UI/` | Формы и тема: главное окно (`MainForm`), контролы (`PowerStatusButton` — строка-переключатель zapret; `StatusControls` — прогресс-бар автовыбора; `UiControls` — кнопки, панели, пикер стратегий), трей, окна установки программы и runtime, настройки и компактные диалоги |

Состав приложения собирается **один раз** в Program (`AppServices`): конфиг и `ConfigService`, `RuntimeLayout`, логгер, инспектор процессов, `ProcessSupervisor`, автозапуск, диспетчер действий `ZapretActionExecutor`. Контекст трея и формы получают готовые зависимости; сервисы в обработчиках не создаются. Главное окно и меню трея потребляют один интерфейс `IZapretManagerCommands` (реализует `TrayApplicationContext`) — добавление действия это правка интерфейса и контекста.

## Основные функции и реализация

### 1. Установка runtime (первый запуск)
Если рядом с `.exe` нет `runtime/`, показывается `RuntimeBootstrapForm`. `RuntimeBootstrapService` качает последний релиз Flowseal через `GitHubReleaseClient`, `RuntimeValidator` проверяет структуру пакета.

### 2. Управление zapret
- **Переключатель / Перезапустить** — `BatStrategyRunner` запускает выбранный `general*.bat`, `ProcessSupervisor` следит за процессом `winws.exe`. Состояние — `ZapretState` (`RuntimeMissing`, `Stopped`, `Running`, `External`); текст для UI получается из него, а не наоборот. Время работы в подписи переключателя обновляет лёгкий UI-таймер раз в секунду.
- **Мониторинг** (`TrayApplicationContext.Monitoring`): завершение своего и внешних `winws.exe` отслеживается сразу через `ManagedProcessWatcher` (ожидание выхода процесса), а опрос раз в минуту нужен, чтобы заметить внешний zapret, запущенный в обход менеджера. Пока внешний zapret работает, опрос идёт раз в 2 секунды: после выхода `winws.exe` служба `zapret` ещё секунду-другую числится запущенной, а к чужому процессу может не быть доступа — об этом Windows событием не сообщает. Штатные остановки идут под `_zapretActionGate`, поэтому уведомление «zapret неожиданно остановился» показывается только при настоящем падении. Иконка трея (`TrayIconSet`: зелёная метка — включён, жёлтая — внешний zapret, серая иконка — выключен) и подсказка обновляются вместе с состоянием; меню трея собирается заново при каждом открытии.
- При состоянии **Внешний zapret** нажатие на переключатель («Действия ›») предлагает контекстное действие. `ExistingZapretStopService` может остановить службу `zapret` и процессы `winws.exe`, но **только** из текущего каталога runtime (проверка путей через `PathComparer`). Для процесса из неизвестного каталога UI показывает предупреждение закрыть его исходным launcher; кнопки остановки нет.
- Перед запуском `BatStrategyRunner` через `ProcessSupervisor` проверяет внешний `winws.exe`, не запускает второй экземпляр и не пытается остановить чужой процесс.

### 3. Стратегии и автовыбор
- `StrategyService` находит доступные `general*.bat` в runtime.
- `StrategyAutoSelectionService` проверяет цели из Flowseal `utils/targets.txt` (со встроенным fallback, строки `PING:` пропускаются) в три этапа: без zapret (`StrategyBaselineReport` — что заблокировано, что ломается на DNS/сертификате), отсев всех стратегий, перепроверка трёх финалистов ещё в двух раундах со сдвигом порядка.
- `HttpStrategyProbe`: каждая попытка = `BrowserTlsHandshake` (сырой TLS 1.3 ClientHello в духе Chrome, ~1,8 КБ; успех — любой TLS-ответ сервера) + HTTPS-запрос через `SocketsHttpHandler` (OK = любой HTTP-код и до 64 КБ тела без обрыва). Первый шаг нужен потому, что Schannel на Windows 10 шлёт TLS 1.2 ClientHello, и стратегии вроде SIMPLE FAKE проходили проверку, хотя браузеры и Discord с ними не работали. Без прокси, новое соединение на каждую попытку, DNS резолвится один раз за прогон, при неудаче — через `DnsOverHttpsResolver` (1.1.1.1 / 8.8.8.8 по IP). Сбои DNS и сертификата (`ProbeOutcome`) в оценку не входят.
- `StrategyAutoSelectionAnalyzer.Rank`: запустилась → доля успеха → баланс YouTube/Discord → текущая стратегия пользователя → медианная задержка (имя — только для детерминизма). Текущая стратегия выигрывает ничью, чтобы автовыбор не менял проверенную на практике стратегию из-за шума в задержке.
- Действия с zapret (`ZapretActionExecutor`) выполняются вне UI-потока; `ProcessSupervisor` сбрасывает сохранённый процесс атомарно, чтобы опрос статуса из UI не терял только что запущенный winws.
- Результат (3 лучшие стратегии + время проверки) сохраняется в `config.json` через `ConfigService` и переживает перезапуск.
- Выбор стратегии доступен и из главного окна, и из меню трея.
- **Итоги**: по завершении — уведомление из двух строк (итог и доля прошедших проверок), без модальных окон (кроме случая, когда zapret не удалось остановить). В окне итог — одной строкой, у строк топ-3 — доля и задержка («94% · 140 мс»); наблюдения прогона (`Notes`) — в подсказке у значка ⓘ, подробности по стратегии — в подсказке у её строки. Подсказки рисует `ThemedToolTip` в теме приложения.

### 4. Обновление runtime
`UpdateCheckService` сравнивает версии по числам (`1.9` < `1.10`, хотфикс `1.9.7b` новее `1.9.7`) и не предлагает «обновиться» на более старый релиз, если последний отозвали. `UpdateService` скачивает ZIP релиза, проверяет digest и обязательные файлы, затем заменяет runtime. При этом:
- сохраняются пользовательские `*-user.txt` и флаги;
- режим IPSet Filter из `service.bat` (none / any / loaded) сохраняется, а сам список берётся свежий из релиза (`IpsetListMode`). У Flowseal режим задаётся содержимым `lists/ipset-all.txt`, а релиз поставляется в режиме none со списком в `ipset-all.txt.backup`;
- старый runtime копируется в `backups/runtime-previous/` для rollback;
- временные файлы чистятся из `temp/`.

### 5. Надёжность
- Повреждённый `config.json` откладывается как `config.json.invalid-*`, создаётся дефолтный.
- `ManagedProcessShutdownService` гарантированно гасит запущенный менеджером `winws.exe` при выходе.
- Логи пишет `FileLogger` в `logs/`.
- Действия с zapret выполняет `ZapretActionExecutor` (протокол — `ZapretActionProtocol`). Всё приложение уже работает с правами администратора, отдельного elevated-процесса нет; конфиг — один объект `AppConfig` в памяти, который сохраняется на диск, но не перечитывается.
- Установку обновления с остановкой и повторным запуском zapret выполняет `RuntimeUpdateCoordinator`; UI отвечает только за диалоги.
- Уведомления (`TrayNotificationService`) показываются собственным окном `ToastWindow` в стиле приложения: без захвата фокуса, со скрытием через 6 с (при наведении ждёт) и действием по клику. Если Windows сообщает, что пользователь занят (`SHQueryUserNotificationState`: игра на весь экран, презентация, «Не беспокоить», блокировка), уведомление отдаётся системному механизму, чтобы не выскакивать поверх.
- Вывод консольных утилит (`schtasks`, `sc`) `CommandRunner` читает в OEM-кодировке системы: в GUI-процессе без консоли .NET иначе декодирует его как UTF-8.
- Все вторичные окна используют общую ширину, метрики кнопок, иконку и центрирование; сообщения подстраивают высоту под текст.

### 6. Единственный экземпляр и права администратора
- `SingleInstanceService`: именованный мьютекс + named pipe. Повторный запуск exe не открывает второе окно, а сигналит первому экземпляру показать уже открытое (в т.ч. из трея). Имена привязаны к хэшу папки приложения, поэтому копия, запущенная с `--no-install`, не конфликтует с установленной. Кроме «покажи окно» pipe принимает «завершись» — им пользуется удаление программы.
- `app.manifest` стоит `asInvoker`, а права повышаются самим приложением (`ElevationService`, перезапуск с `runas`) **после** проверки single-instance. Поэтому UAC показывается один раз при первом запуске, а повторный запуск для вывода окна в фокус проходит без запроса прав.

### 7. Автозапуск с Windows
- `AutostartService` создаёт задание, имя которого содержит хэш полного пути exe. Перед перезаписью или удалением сервис сверяет в XML задания путь exe и аргумент `--autostart`. Задание читается через COM-API Планировщика (`ScheduledTaskReader`): отсутствие определяется по коду ошибки, а не по тексту `schtasks`, который зависит от языка Windows. Создание и удаление идут через `schtasks` с проверкой кода выхода.
- В режиме `--autostart` главное окно не показывается, приложение остаётся в трее и после запуска UI-цикла включает последнюю выбранную стратегию.
- Если runtime или стратегия отсутствуют, фоновой запуск не открывает модальных окон и сообщает о проблеме через трей.

### 8. Установка, удаление и самообновление
- **Установка** (`InstallFlow`, `AppInstaller`, `InstallPaths`). Запуск не из папки установки (обычно — скачанный файл) ничего не создаёт рядом с собой: показывает `InstallForm`, копирует exe в `%LOCALAPPDATA%\Programs\Zapret Manager\`, создаёт ярлыки (`ShellShortcut`, COM ShellLink) и запись в «Приложениях» (`HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall\ZapretManager`), затем запускает установленную копию с `--first-run` — та сразу качает Flowseal. Всё это идёт **до** запроса прав и от имени пользователя, поэтому файлы попадают в его профиль, даже если UAC подтвердят паролем другой учётки. Если установленная версия не старее скачанной, просто открывается установленная.
- **Удаление** (`UninstallFlow`, `--uninstall` из «Приложений»): повышает права, просит работающий экземпляр завершиться штатно (он сам останавливает свой zapret), останавливает оставшийся свой `winws.exe`, снимает автозапуск, ярлыки и запись и удаляет папку через `cmd` после выхода процесса.
- **Самообновление** (`ManagerUpdateService`, `ExecutableReplacer`): проверяется последний релиз `elcapue/zapret-manager`, берётся ассет `ZapretManager-<версия>-win-x64.exe`, SHA-256 из релиза **обязателен**. Работающий exe нельзя перезаписать, но можно переименовать: он уходит в `.old`, новый ложится на его место и запускается с `--elevation-handoff` (ждёт mutex), а старый выходит **без остановки zapret** — новый подхватывает `winws.exe` по `ManagedProcess` из конфига. `.old` удаляется при следующем старте; если новый не запустился — откат.
- Проверка обновлений сначала смотрит менеджер, потом Flowseal. Ошибка проверки менеджера (нет сети, у репозитория нет релизов) только пишется в лог.
- Релиз собирает `.github/workflows/release.yml` по тегу `v*`: тесты, сборка, сверка тега с `<Version>` в csproj, релиз с ассетом и SHA-256.

## Инварианты: что нельзя менять и почему

Эти решения выглядят как «магические константы», но их изменение сломает поведение для существующих пользователей:

1. **`asInvoker` в манифесте + self-elevation** — не возвращать `requireAdministrator`. С `requireAdministrator` Windows показывает UAC до запуска кода, и даже повторный запуск (просто показать окно) требует прав администратора.
2. **Имена мьютекса/pipe привязаны к папке приложения** — не делать их глобальными. Скачанный файл находит по ним установленную копию, а копия с `--no-install` не мешает установленной.
3. **Имя ассета релиза `ZapretManager-<версия>-win-x64.exe` и адрес репозитория** — по ним установленные копии ищут обновления. Сменить их — значит оставить уже установленные версии без обновлений.
4. **Установка до повышения прав** — не переносить её после UAC: иначе при UAC с паролем другой учётки программа встанет в чужой профиль.

## Локальные данные

Всё лежит в папке установки `%LOCALAPPDATA%\Programs\Zapret Manager\`, рядом с exe:

```
Zapret Manager.exe        # сам менеджер (+ .old сразу после самообновления)
runtime/                  # установленный Flowseal
config.json               # настройки + результат автовыбора
backups/runtime-previous/ # бэкап для rollback
temp/                     # временные файлы обновлений
logs/                     # логи
```

## Разработка и релизы

```powershell
dotnet test ZapretManager.sln -c Release                                # тесты
powershell -ExecutionPolicy Bypass -File .\tools\publish.ps1            # single-file .exe в artifacts/
powershell -ExecutionPolicy Bypass -File .\tools\install-local.ps1      # поставить сборку поверх установленной
```

- Запуск без установки — параметр `--no-install` (в IDE подставляется из `Properties/launchSettings.json`).
- `install-local.ps1` нужен потому, что у тестовых сборок одна версия, а установщик сравнивает только её. Скрипт просит работающий менеджер закрыться служебным аргументом `--request-primary-exit <папка>` (имя pipe для папки вычисляет само приложение — протокол `SingleInstanceService` нигде снаружи не дублируется), заменяет exe и запускает новый (останется подтвердить UAC); runtime и настройки не трогаются.
- Релиз: поднять `<Version>` в `ZapretManager.App.csproj` и отправить тег `v<версия>` — остальное делает `.github/workflows/release.yml`.

## Покрытие тестами

Покрыто поведенческими тестами: обновления runtime (`UpdateService`, `RuntimeValidator`, `RuntimeUpdateCoordinator`), диспетчер действий `ZapretActionExecutor` (маппинг видов действий, исключения, отмена с восстановлением), автовыбор (`StrategyAutoSelectionService` + probe/handshake), установка и удаление (`AppInstaller`, `ExecutableReplacer`), single-instance, автозапуск, форматирование итогов (`StrategyCheckFormatter`), защита перед Kill (`WinwsProcessInspector.MatchesExpectedProcess`), классификатор отказа UAC (`ElevationService`).

Без тестов сознательно: чисто UI-склейка `TrayApplicationContext` (потоки и диалоги), оркестрации первого запуска (`InstallFlow`/`UninstallFlow`/`RuntimeBootstrapForm`), мониторинг состояния в трее. WinForms-тесты бегут последовательно (`DisableTestParallelization` в `AssemblyInfo.cs`): параллельный запуск коллекций на MTA-потоках давал flaky-взаимовлияние.
